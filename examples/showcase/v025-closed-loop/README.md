# v0.2.5 — Closed-Loop Governance Showcase

A complete walkthrough of the governance loop introduced in v0.2.5:
profile authored → recipe shared with the agent → governed session
runs → trace carries profile-driven advisory flags → analyzer
surfaces them in dedicated report sections.

## Files in this directory

| File | What it is |
|---|---|
| `profile.yaml` | Operator-authored governance profile (drop at `~/.sentience/profile.yaml` to activate machine-wide). |
| `CLAUDE.md` | Recipe template the operator places in their project so the agent knows what's expected of it. |
| `session.jsonl` | Synthesized governed session trace (generated by the demo). |
| `analyzer_output.md` | Pre-rendered analyzer report (generated by the demo). |

The trace and the report are regenerated by
`examples/v025_closed_loop_demo.py` and are byte-stable across runs
(pinned by `tests/test_v025_closed_loop_demo.py`).

## What the loop looks like

1. **Operator authors `profile.yaml`.** This one declares
   `demand_at: first_write` (POL-001 fires once per session, not
   per-event), three task-boundary signals (`dir_change`,
   `file_type_shift`, `read_to_write_transition`), and three
   high-consequence tool patterns (`rm -rf`, force-pushes, `.env`
   writes).

2. **Operator places `CLAUDE.md` in the project.** The recipe tells
   the agent what the profile asks of it, in plain language. The
   agent and the wrapper read different artifacts (recipe vs YAML)
   but they encode the same expectations — the recipe is the human
   surface, the profile is the machine surface.

3. **A session runs.** In this showcase, the agent:
   - Declares its intent up front (refactor middleware).
   - Reads a file (Turn 1, in-scope).
   - Writes the same file (Turn 2 — fires `TASK_BOUNDARY_CROSSED`
     because of the `read_to_write_transition` signal).
   - Runs `rm -rf` on a scratch dir (Turn 3 — fires
     `HIGH_CONSEQUENCE_DETECTED` because of the `Bash:.*rm.*-rf.*`
     pattern).

4. **The trace carries profile-driven advisory flags.** Every event
   in `session.jsonl` carries `profile_fingerprint: 5c3ce82958dd`
   at the envelope level. The `AGENT_REGISTERED` event additionally
   carries `profile_loaded: true` and `profile_schema_version: 1`
   in its payload.

5. **The analyzer surfaces the new flags.** Run the analyzer on
   the trace — `analyzer_output.md` shows what the operator sees:
   - `## Profile` section (fingerprint + schema version)
   - `## High-consequence operations` table (the `rm -rf` event)
   - `## Task boundaries crossed` table (the read→write transition)

## Running the demo

```bash
python examples/v025_closed_loop_demo.py
```

The demo loads `profile.yaml`, builds the synthesized trace, runs
the analyzer, and writes `session.jsonl` + `analyzer_output.md` back
into this directory.

Verify byte-stability:

```bash
python examples/v025_closed_loop_demo.py
git diff --exit-code examples/showcase/v025-closed-loop/
```

## Re-analyze via the CLI

```bash
sentience analyze undeclared-intent examples/showcase/v025-closed-loop/session.jsonl
```

You'll see the same CLI render the demo produces — the analyzer is
a pure function over trace contents, so the result is identical
whether invoked through the demo script or the CLI.

## What this is **not**

This showcase exercises observability only — the profile shapes what
the trace surfaces, not what the agent can do. The `HIGH_CONSEQUENCE`
and `TASK_BOUNDARY` flags are advisory; nothing was blocked. Policy
enforcement (block, deny, prompt-and-confirm) is paid-tier
territory; the schema reserves the vocabulary (`prompt`, `block`,
`deny` are recognized as `on_match` values but warn-and-fallback to
`flag` in the open tier).
